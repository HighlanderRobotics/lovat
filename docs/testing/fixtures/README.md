# Retained cross-app contracts

`contract-v1.json` is a hand-authored 2026 compatibility corpus. It contains no
captured scouting data, identities or credentials. Both source teams, robots,
roles and private-note markers are fictional. Do not replace these examples with
production exports. Review changes to expected values independently of production
implementations and record the reasoning in the PR.

The Collection loader validates and serializes reports with production
`sendReport` and checks idempotent legacy migration. Server tests submit those
serialized payloads to the real HTTP app with disposable PostgreSQL and Redis,
check persisted points and source-team/private-note isolation through real JWT
middleware, and write the actual picklist response. Dashboard decodes that
response with its production API extension and tests picklist round trips.
No application imports another application's code.

The `Cross-app contracts` CI job runs these stages in order. Ordinary app suites
also consume the corpus independently. Expectations are fixed JSON, not values
generated by the system being tested.

Arithmetic is included in the JSON: Alpha's robots score 45 and 16 points, giving
mean 30.5 and population standard deviation 14.5, hence z scores +1 and −1.
Bravo's private observation scores 15 and must not alter Alpha's first-robot score
or reveal Bravo's note. Viewers also exercise cache hits across identities.
Old broken-undo payloads retain their compatibility behavior; a malformed current
payload is rejected without leaving a partial report.

Fixture and Server/database changes select the contract job and affected
consumers. Artifacts retain logs and actual synthetic JSON on failure, and failures
fail the aggregate. Database tests refuse non-loopback services or names other
than `lovat_test` and Redis database 15.

## Local execution

Install the app dependencies with their pinned toolchains. Start disposable
PostgreSQL 16 and Redis (loopback only), create an empty `lovat_test` database,
and apply `npm --prefix packages/db run db:deploy` with that explicit URL. Then:

```sh
DATABASE_URL=postgresql://lovat_test:lovat_test@127.0.0.1:5432/lovat_test \
REDIS_URL=redis://127.0.0.1:6379/15 LOVAT_DB_TEST=1 \
./scripts/check-contracts.sh
```

The script locates the pinned Node binaries under the usual nvm installation
(or `LOVAT_NODE_ROOT`); Flutter 3.35.4 must be on PATH. It refuses other service
hosts/database names and never loads a private `.env`. It retains stage logs,
serialized payloads, the actual Server response and HTML under `contract-report/`.
The root `check-all.sh` includes this check, so it now needs these disposable
services as well as the app toolchains. CI provisions its own isolated services.

Successful main runs publish `/lovat/contracts/`. Failure artifacts stay on their
run and do not replace the last successful public report.
